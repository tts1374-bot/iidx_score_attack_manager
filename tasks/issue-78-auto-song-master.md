# Issue #78: 曲マスタの自動取得・更新

- 区分: implementation-authorized / Plan Mode。実装ブランチに同梱する作業記録。
- BASE_SHA: 32b0373819700ad62f774c83ea1718df857aece2
- 目的: 初回を含め、起動後・ホーム復帰・可視状態への復帰時に配布済み曲マスタを自動取得する。
- 非目的: マスタ生成・配布、トースト配置、Web Locks、委譲チャネル、PWA/SW、DB schema、保存形式の変更。

## 方針・変更点

- 自動確認の最小間隔は5分。実行開始時刻を記録し、完了時にも時刻を更新する。失敗や長時間の取得完了直後に連続実行しない。定期ポーリングは追加せず、ホーム復帰・visibility/focusを契機にする。
- bootstrapの既存スナップショット取得完了後、可視ホームかつbusy・作成保存・QR取込・ダイアログなどの操作がない場合にのみ開始する。それ以外では延期し、安全条件が成立した時点で再評価する。操作終了だけを契機に新規確認はしない（起動・ホーム復帰・画面復帰からの保留要求だけ再開）。
- 既存SongMasterService.updateIfNeeded()を利用。自動・手動のApp側処理も一本化し、重複通知・スナップショット更新を防ぐ。
- 更新開始後に発生した画面遷移や詳細取得は、同一更新Promiseの終了後に実行して、曲マスタの適用と参照を重ねない。
- 新版取得中は「新しい楽曲データが見つかったため更新中です。」、初回は「楽曲データを取得中です。」、成功時は「楽曲データを更新しました。」を表示する。
- 自動の最新版確認・保存済みキャッシュで継続できる通信失敗はトーストを出さない。更新成功は通知し、失敗はホームの再試行案内とログに残す。未取得時も設定や再試行へ到達できる表示とする。
- 手動更新・強制再取得は確認間隔を無視して利用可能。既存の検証・OPFS書き込み・メタデータ形式は維持する。

## 対象・影響

- web-app: App.tsx、自動確認用hookとテスト、必要な統合テスト、ja/en/ko翻訳。
- db: song-masterサービスに後方互換の任意callbackを追加し、検証済みlatest.jsonで取得が必要と判明した時だけ通知する。取得・検証・保存は既存処理を利用し、異常系・同時更新テストを補強する。
- ユーザー: 初回ダウンロード、ホームでの自動更新、再試行案内が変わる。取得中の新規画面遷移は完了後に進む。
- データ・互換性: DB schema / user_version / def_hash / payloadは変更しない。
- PWA・保存・起動: 既存bootstrapやPWA登録順序は変えず、初期化完了後の独立した更新処理を追加する。

## 検証

- 初回・新版・最新版、5分境界、focus/visibility、操作中の延期と再開、手動との競合。
- 通信失敗・不正JSON・ハッシュ不一致・スキーマ不一致で旧マスタ維持、未取得時の再試行。
- 適用中の画面遷移・詳細取得の待機、成功後の作成/取込の有効化。
- 曲検索・譜面参照の既存DBテスト、web-app/dbテスト、型検査・ビルド、対象画面の表示確認。
- 差分・UTF-8 BOMなし/LF・lockfile不変を確認する。
